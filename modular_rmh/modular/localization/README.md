# Перевод (localization)

Русский поверх игры для игроков с русским языком интерфейса. Сервер всегда пишет по-английски, перевод
накладывается для каждого читателя отдельно; игрок на английском не получает ничего лишнего.

## Язык

- Настройка аккаунта `/datum/preference/choiced/ui_language` (PREF_PLAYER, ключ `ui_language`, `"en"` / `"ru"`,
  по умолчанию `"en"`) в `modular_rmh/code/modules/client/preferred_language.dm`. Её хранит датум настроек, поэтому
  она переживает переподключение и смену раунда. При первом входе берётся из старых ключей `preferred_ui_language`
  и `character_creator_lang`.
- Переключение: глагол **Change Preferred Language** (OOC) или переключатель в редакторе персонажа. Чат
  переключается сразу, открытые окна обновляются.
- В коде: читать — `get_preferred_ui_language(mob)` / `get_client_ui_language(client)`, менять —
  `prefs.set_ui_language(language)`.

## Как переводится

- **Чат** — в панели игрока (`tgui/packages/tgui-panel/localization/`). Сервер отдаёт словарь
  (`/datum/asset/json/chat_localization`) только читателю русского. Каждая текстовая нода: точная строка, иначе
  первый подходящий шаблон, иначе остаётся английской. `$2|acc` в шаблоне склоняет захват по словарю имён и по
  падежам, которые игроки написали для персонажей.
- **Осмотр и наведение мыши** — на сервере. Имена и описания предметов привязаны к типу (`/obj/item/foo = ...`):
  при загрузке сервер берёт английский текст из самого типа. Поэтому потомок, не объявивший свой `name` или `desc`,
  получает перевод родителя, а потомок со своим текстом остаётся английским, пока ему не добавят строку. Если
  текст типа в коде переписали, остаётся старый перевод: его надо проверить руками. Описания, которые игра
  собирает сама, — шаблоны с ключом `^`; «описание + дописанные предложения» (начинки, качество готовки)
  переводится по частям, только если переведены все. Имена персонажей не переводятся; метка крови идёт после имени
  («меч в крови»).
- **Что на ком надето** — строка осмотра «She has <b>имя</b> on her chest.» приходит в чат тремя текстовыми нодами.
  Имя переводит сервер (именительный падеж), начало и место — шаблоны в `rmh_patterns.txt`, порознь и так, чтобы
  имя не склонять: «— железная кираса на груди.», «— меч в правой руке.». Место называет сама игра для каждого
  слота; новый слот в `get_examine_gear()` требует своей строки-шаблона.
- **Надписи над картой** (balloon alert) — серверный строгий словарь: не оставляет английский посреди надписи.
- **Падежи имени персонажа** игрок пишет сам (глагол **Склонения имени / Name Cases**); пустой падеж — имя как есть.

Не переводятся слова игроков, OOC, логи сервера и имена, которые игра собирает на ходу («tasty bread»).

## Строки

`strings/*.txt`: `ключ = значение`, разделитель — первое ` = `, `#` — комментарий, единственная экранировка — `\n`.
Ключ с `/` — путь типа, с `^` — шаблон, иначе — английский текст. Имена склоняются:
`ключ = им. | род. | дат. | вин. | твор. | предл.`.

- Импортированные (руками не правятся): `items`, `descriptions` — имена и описания предметов, по путям типов;
  `words` — слова без своего типа (навыки, материалы, места), `titles` — должности, `nouns` — части тела,
  `honorifics` — титулы; `fragments`, `speech`, `medical`, `world`, `status`, `rpg_fragments` — точные строки
  чата; `patterns` — шаблоны чата; `maptext` — надписи над картой.
- Свои: `rmh_items`, `rmh_titles`, `rmh_descriptions`, `rmh_fragments`, `rmh_patterns`, `rmh_maptext` — при
  совпадении ключа побеждают импортированные. Части тела побеждают имена: «chest» — грудь, а не сундук.
- Новый предмет: строка `/тип/путь = перевод` в `rmh_items` и `rmh_descriptions`, на тот тип, что сам объявляет
  текст. Строка на тип, которого нет в билде, валит юнит-тест `localization_strings`.
- Текст, который код собирает макросом или выражением (`name = BODY_ZONE_HEAD`, `desc = span_hierophant("...")`),
  проверка прочитать не может и просит строку на сам тип; в описании разметка пишется как в игре.
- Текст, который в коде уже написан по-русски, строки не требует.
- Английский ключ — текст из кода буква в букву. Частный шаблон пишется выше общего. Род захвата неизвестен —
  безличный глагол или настоящее время, без прилагательных. В чате — никаких голых существительных и строк из
  одного-двух слов.

## Сколько это стоит серверу

Замеры — отдельный мир BYOND 516.1688 с этими же файлами строк (11 600 строк, 2,1 МБ), по два прогона; на живом
сервере не снималось.

- Поиск перевода — микросекунды: проверка языка читателя 0,6 мкс, имя 2 мкс, строка из кэша 0,7 мкс, описание
  0,5–19 мкс. Дорога одна вещь: надпись над картой, которой нет в словаре и которую сервер видит впервые, — около
  пятисот шаблонов подряд, 0,25 мс; ответ запоминается.
- Дорога была загрузка. Файлы строк отсортированы по ключу, а BYOND вешает каждую новую строку, пришедшую по
  порядку, уровнем ниже предыдущей; тысяча таких строк разом заставляет движок пересортировать все строки мира.
  Загрузчик резал файл на строки целиком: 0,33 с в пустом мире, 1,2 с при 400 тыс. строк в мире, 2,4 с при 800 тыс.,
  одним фризом — причём словарь описаний строился при первом осмотре русским игроком, посреди раунда.
- Теперь файл читается блоками по 16 КБ (`localization_blocks`), пары блока используются и отпускаются до
  следующего: 0,27–0,40 с при любом размере мира. Все словари строятся при старте, вместе с ассетом чата.
- Правило для правок загрузчика: никогда не делить файл строк на строки целиком и не держать все его пары разом.
  Готовый JSON тут не выручает сам по себе: в порядке ключей он грузился те же 0,7 с, в перемешанном — 0,09–0,6 с.
- Словарь чата — 3,8 МБ на диске (`json_encode` пишет кириллицу как `\uXXXX`), текста в нём около 1,4 МБ. Едет он
  транспортом ассетов сервера. С `ASSET_TRANSPORT webroot` (CDN) клиент берёт файл по ссылке с хешем: с gzip это
  несколько сотен килобайт мимо игрового сервера. Если webroot не задан или не прошёл проверку конфига, сервер сам
  остаётся на `browse_rsc`, и файл идёт через DreamDaemon — только русскому читателю, когда его панель готова: из
  фоновой рассылки `ASSET_SIMPLE_PRELOAD`, которая шлёт все ассеты всем, словарь исключён.
- Кеш `browse_rsc` живёт, пока запущен клиент. Сервер помнит имя и md5 отправленного (`asset_data.json` у клиента),
  поэтому переподключение и новый раунд файл заново не шлют; после перезапуска клиента и после правки строк (новый
  хеш) он уходит снова. Адрес файла панель получает раньше, чем файл доехал, поэтому загрузку словаря она
  повторяет около двух минут (`tgui-panel/localization/handlers.ts`), а не остаётся на английском.

## Проверка

На каждом PR шаг **Check Item Translations** (`tools/ci/check_item_translations.py`) считает `/obj/item` по текущему
коду: сколько имён и описаний переведено, сколько нет и какие строки осталось написать. Шаг падает, пока такие строки
есть. Потомок переведённого родителя переведён вместе с ним, одинаковый текст переводится одной строкой. Тот же список
локально: `python tools/ci/check_item_translations.py` из корня репозитория.

Скрипт `strings_against_build.py` лежит в `scripts/` репозитория ai-skills, описание — `docs/localization-tooling.ru.md`.

- `python <ai-skills>/scripts/strings_against_build.py missing . modular_rmh/modular/localization/strings > missing.tsv`
  — всё без перевода: вид (`name` или `desc`), тип, сколько потомков показывают тот же текст, английское имя и
  описание. В списке только типы, которые сами объявляют текст: потомок с переведённым родителем в него не попадает.
  `--prefix obj/item`, `--kind desc` сужают список, а с `--baseline missing.tsv` видно только новое с прошлого
  раза, и код выхода 1 — если новое есть.
- `... check . modular_rmh/modular/localization/strings --out tmp/localization` — строки против исходников билда:
  строки, которым ничего не соответствует, битые шаблоны, сводка покрытия. Код выхода 1 — есть битые строки.
  `import` пересобирает импортированные файлы.
- Юнит-тесты — в конце `code/localization.dm`; движок чата — `bun test` для `translate.test.ts`.

## Подключение

`.dme` включает только `preferred_language.dm`, тот последней строкой — `code/localization.dm`. Код модуля — файлы
не меньше 500 строк, следующий подключается такой же строкой `#include` в `preferred_language.dm`.

Правки вне модуля: `tgui-panel/chat/renderer.tsx` (`translateNode`), `tgui-panel/events/listeners.ts`,
`preferences_savefile.dm`, `contract_machine.dm`, `questboard.dm`, `character_creator.dm`, `tools/deploy.sh`,
`tools/ci/check_item_translations.py`, `.github/workflows/ci_suite.yml`; `carbon/examine.dm` (каждый слот называет
место, шесть слотов больше не печатают его отдельной строкой) и `simple_animal/examine.dm` (описание животного
идёт через `get_examine_desc()`).

## Что перевод пока не покрывает

Имя или описание доходит до игрока мимо перевода (обзор кода 2026-11-10, по убыванию заметности): книга рецептов и
её ассет `recipe_book_db`; списки выбора (`browser_input_list` у наковальни, `tgui_input_list`, родной `input()`);
подписи радиального меню, кнопок действий и статусов (экранные объекты исключены из перевода наведения); осмотр
экранного объекта шифт-кликом; панель «рассмотреть ближе» (`ExaminePanel`); панели добычи, склада и торговцев; окна
`/datum/browser` (раздевание, разносчик, стюард); окно `{?}` свойств предмета (имя в верхнем регистре не находится
в словаре); тело всплывающих подсказок в чате; надписи рунного чата от предметов и названия местностей.

Файлы `strings/` игра читает во время работы, поэтому `tools/deploy.sh` копирует их рядом с `.dmb`: без них CI
запускает мир с пустым словарём и падает на рантаймах.
